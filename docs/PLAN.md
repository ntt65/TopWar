## 1. 목표

세로 화면 3D 러너 슈터. 지휘관이 병사 무리를 이끌고 전진하며 캡슐을 쏴서 병력·무기를 늘리고, 적 무리와 보스를 돌파한다.

**첫 마일스톤(R1)의 완료 조건:** 1분짜리 한 판이 **게임처럼 보이고 재미있다**. 처음부터 애니메이션 캐릭터, 이펙트, 피해 숫자, 팝업, 카메라 흔들림이 들어간다. 박스 프로토타입 단계는 없다.

## 2. 마일스톤 개요

| 마일스톤 | 목표 | 끝났을 때 Play로 보이는 것 |
| --- | --- | --- |
| **R1 수직 슬라이스** | 1분짜리 한 판 완성 | 로비 Start → 다리 위 러너 한 판 → 보스 → 승리/패배 결과 → 로비 |
| **R2 성능** | 병사·적 수백 명, 총알 수천 발에서 60fps | 스트레스 장면(캐릭터 400 + 총알 2000)이 기기에서 60fps |
| **R3 스테이지와 성장** | 스테이지 5개, 로비 영구 강화, 저장 | 스테이지 1→5 진행, 보석으로 강화 후 더 멀리 감 |

### 3.2 R1 완료 기준 (Play로 확인)

1. 로비에서 Start를 누르면 1초 안에 러너가 시작된다.
2. 처음 10초 안에 캡슐을 부숴 병사가 늘어나는 것이 보인다.
3. 게이트 선택이 결과를 바꾼다 (`x2` vs `+5`).
4. 적 무리에 부딪히면 병사가 줄고, 무리를 다 잃을 수 있다는 긴장이 있다.
5. 보스전에서 체력 바가 깎이는 것이 보이고, 승리 시 `VICTORY!` 연출이 나온다.
6. 한 판이 60~80초다.
7. 에디터 Device Simulator(중급 안드로이드)에서 끊김 없이 돈다. 병사 최대 약 120명.
8. 화면에 기본 도형(큐브·캡슐) 캐릭터가 없다.

### 3.3 기존 코드 처리

- `GameBootstrap`은 진입점으로 유지한다. 로비 Start가 디펜스 대신 러너를 시작하게 바꾼다. 디펜스 코드(`Core/Battle`, `Core/Grid`, `Game/Battle` 등)는 지우지 않고 호출만 끊는다.
- 재사용: `PlayerProgress`, `ProgressStore`, `LobbyScreen`, `ResultScreen`, `UiFactory`, `CounterTable`, `UnitType`.
- 씬 편집은 필요 없다 (씬에는 `GameBootstrap` 하나).

## 4. R2 성능

- [ ] 성능 측정 장면: 캐릭터 400, 총알 2000을 강제로 띄우는 디버그 모드 + 화면 FPS·ms 표시
- [ ] 캐릭터 렌더링을 VAT(정점 애니메이션 텍스처) + GPU 인스턴싱으로 전환 ([architecture.md 5장](design/architecture.md))
- [ ] 애니메이션 굽기 에디터 도구 (메뉴 한 번으로 FBX → VAT 텍스처)
- [ ] 레벨별 외형 단계(크기·색) 인스턴스 데이터로 표현
- [ ] 완료 기준: 중급 안드로이드 실기기(또는 사용자 기기)에서 스트레스 장면 60fps, 시뮬레이션 3ms 이하

## 5. R3 스테이지와 성장

- [ ] 스테이지 데이터를 구간(패턴) 조합으로 생성 (스테이지 2~5)
- [ ] 로비 영구 강화 개편: 병종 공격력, 시작 병사 수, 시작 무기 단계 (기존 `BaseHealth`, `GridSize` 대체)
- [ ] 보상: 승리 보너스 + 진행 거리 비례
- [ ] 저장 데이터 이전 (v1 저장 키와 충돌하지 않게)
- [ ] 완료 기준: 스테이지 1~5를 강화하며 진행, 앱을 다시 켜도 유지

## 6. R4 연출·사운드·밸런스
